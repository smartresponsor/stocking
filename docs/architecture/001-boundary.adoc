= Stocking Boundary

== Purpose

owns inventory availability, stock levels, reservations, incoming quantities, adjustments, and movements across stock locations.

== Owns

* stock-kept resource identity
* location-scoped stock levels
* available-to-promise
* reservation, release, and expiry lifecycle
* incoming quantities and replenishment projection
* stock adjustments and reconciliation
* stock movement ledger
* backorder and oversell policy primitives
* allocation facts consumed by fulfillment and shipping

== Does not own

* catalog product ownership; Cataloging owns it
* order lifecycle; Ordering owns it
* shipment execution; Shipping owns it
* location/address truth; Locating and Addressing own it
* generic file/object storage

== Current materialization scope

The repository now implements the RC-critical Stocking core: inventory-owned stock item identity; location-scoped on-hand/reserved/incoming facts; strict physical invariants; durable reservation lifecycle; replay-safe idempotent mutations; Objecting-backed optimistic locking; append-oriented bucket-delta movement facts; transfers; reconciliation; supply/replenishment mutations; strict ATP; and explicit incoming/backorder promise policy.

Ordering and Shipping remain consumers/coordinators rather than dependencies of Stocking. Ordering owns order lifecycle and its InventoryGatewayInterface/SKU vocabulary; Shipping owns shipment execution and explicitly does not own inventory reservation. Composition code must translate sibling identities into Stocking-owned stock-item/location operations without moving those truths into this component.
